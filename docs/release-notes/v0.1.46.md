# KayaDB v0.1.46 — M15 remaining tracks

**Release date:** 2026-06-30  
**Milestone:** M15 complete

## Highlights

- **Client token auth** — `CLIENT\x00` framing for PUT/GET/DELETE/SCAN/STATS (opcodes 1–4, 6) via `--client-token` / `KAYA_CLIENT_TOKEN`
- **Audit logging** — append-only JSONL at `{data_dir}/audit.jsonl`
- **Prometheus** — `/metrics` on `--metrics-addr` (default `127.0.0.1:9090`)
- **Go client** — `clients/kaya-go/` with leader redirect and client token
- **Conformance suite** — `docs/clients/conformance/vectors.json` + Rust runner
- **HELLO handshake** — opcode 0, `PROTO_VERSION = 1`
- **`kayactl watch`** — poll cluster STATS on an interval
- **Deploy examples** — Docker Compose (`deploy/docker/`) and Kubernetes (`deploy/k8s/`)
- **`kaya-ebpf`** — workspace stub crate restored

## Install

```bash
# From GitHub Release assets (recommended)
# Download kayadb-v0.1.46-<target>.tar.gz or .zip for your platform

# Or via crates.io (after publish)
cargo install kayactl --version 0.1.46
cargo install kaya-server --bin kayadb-server --version 0.1.46
```

## Upgrade notes

- When `--client-token` is set, data-path RPCs require the token prefix; HEALTH (opcode 5) stays open for probes.
- Audit logging defaults **on** when any token is configured; use `--no-audit-log` to disable.
- See [CHANGELOG](CHANGELOG.md) and [security guide](security.md) for accepted deployment risks.
