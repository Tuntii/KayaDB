# KayaDB v0.2.0

**Release date:** 2026-09-05  
**Milestone:** First 0.2 line (M16–M25 production path + post-candidate residuals)

v0.2.0 is a coordinated cut of the v0.2.0 candidate, not an unqualified production-SLA claim. Residual risks (physical key copy on migrate, 2PC forwarding on TLS, quotas/RBAC, Dashboard Phase B/C, Zig client) stay documented in [ROADMAP.md](../ROADMAP.md).

## Highlights

- **Range migrate:** live `MOVE_RANGE` (21) routing cutover, durable Raft-replicated range meta, orphan group reclaim after merge
- **Transactions:** parallel 2PC prepare/commit/abort, durable global decision log, HLC uncertainty wait/clamp
- **Security:** online encryption key rotation (KEK/DEK dual-key window), named tenant isolation (`--tenant-file`)
- **Ops:** Dashboard v2 Phase A (`/v1/cluster`, `/v1/leadership`, range `healthy`, `/v1/errors`)
- **Clients:** TypeScript TXN + RetryPolicy; Zig client deferred/wontfix
- **Correctness:** WGL MUS enumeration + `kaya-wgl` JSONL explorer; Jepsen multi-range bank nightly
- **Deps/CI:** OpenTelemetry 0.32, io-uring 0.7, rand 0.10; Actions checkout v7 / cache v6 / download-artifact v8; documented `workflow_dispatch` fallback

## Install

```bash
# GitHub Release assets (recommended)
# Download kayadb-v0.2.0-<target>.tar.gz or .zip for your platform

# crates.io (after publish)
cargo install kayactl --version 0.2.0
cargo install kaya-server --bin kayadb-server --version 0.2.0
```

Embedded engine:

```toml
kaya-engine = "0.2.0"
```

## Upgrade notes

- Workspace crate versions move from `0.1.113` to `0.2.0`. Path deps in `Cargo.toml` match.
- Tenant isolation is opt-in (`--tenant-file` / `KAYA_TENANT_FILE`). Prefix ACL still works; when both are set, both must pass.
- `MOVE_RANGE` changes placement, not bytes (shared engine). Physical key copy remains spec'd, not shipped.
- Dashboard `/health` is unchanged (`{"ok":true}`). New routes are under `/v1/`.
- See [CHANGELOG](../../CHANGELOG.md) and [security](../security.md) §7 for accepted risks.
